# G3 变更案例执行记录

本目录保存 [注册草案](../../acceptance/v0.1/registry.draft.json) 中 M01～M20 的实际执行结果。**注册仍是草案，种子、角色绑定和 oracle 都由同一会话作者编写，没有独立审阅和冻结清单；10 个登记为自然语言入口的案例以等价的类型化 IR 执行。因此结果只能作为“证据不足”的观测，不是正式 G3 通过。**

## 种子与 oracle

[scripts/g3_seeds.py](../../scripts/g3_seeds.py) 按 C01～C10 的尺寸生成 10 个可编辑原生工程：命名参数、Feature 关系、场景层级与共享零件定义。验收体积、包围盒来自案例尺寸的闭式公式，不来自几何测量。每个种子在执行前写明角色绑定，把注册表中的语义角色（如 `stock.extrude`、`spacer.instances`）展开为确切 Feature 名称。

## 每个案例检查什么

[scripts/g3_changes.py](../../scripts/g3_changes.py) 从独立验证过的新种子开始，把变更做成未发布候选：

1. `deep3d explain` 的失效集合与角色 oracle 两个方向比较（多报、漏报、保留角色被误判、新增和删除 Feature）；
2. 变化分类：定义、草图求解、几何、放置、交付、证据（改名只能落在交付类）；
3. 实际执行的 Feature 必须等于失效集合，其余从 ActionCache 复用且字节与种子一致；
4. 候选通过 BREP/STEP 独立验证后按原 Head 采纳；应拒绝的案例检查 Head 和历史不变；
5. 在另一缓存命名空间禁用缓存全量重建，逐 Feature、逐节点及整体比较拓扑计数、体积与双向差集体积；
6. 用点分类探针检查体积/包围盒不能覆盖的关系（孔位、鳍片、槽端、隔套位置等），并检查 BOM 数量和 STEP 实例名。
