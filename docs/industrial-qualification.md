# 工业 CAD 资格验证与交付门禁

日期：2026-10-26。状态：待实现的开发规格草案 v0.1。

本文件把“工业级别”拆成能够验证的产品能力和发布门禁。首个解析法兰的 OCCT 构造、测量、反例和 STEP 自写自读已经进入实施，记录见 [CAD 基础模块](cad-foundation.md)；完整互操作、故障演练与工业资格仍未完成。文中的数值是建议验收目标，需要在 M0/M1 的真实样本上校准并版本化；它们不是现有成绩、行业认证或制造质量承诺。

首个产品资格范围是：以精确 B-Rep 为权威几何、能够持续编辑参数和可靠恢复任务的机械 CAD Agent。先支持经验证的棱柱类、回转类机械零件，再扩展装配和复杂曲面。原方案的城堡与 GLB 例子保留为远期方向，不能充当工业 CAD 的首批验收案例。

## 1. 资格范围与证据等级

| 等级 | 可以宣称的能力 | 必须提供的证据 |
| --- | --- | --- |
| 开发原型 | 完成指定零件的建模闭环 | 原生工程、测试输入、输出和失败报告 |
| CAD 基础资格 | 在明确操作及尺寸范围内，尺寸、拓扑、编辑、导出符合契约 | M0～M2 全部通过的版本绑定报告 |
| 工程试用候选 | 有受控 Agent、工程编辑与刚性装配 | M3～M4 功能与失败回归报告 |
| 限定范围工业试用资格 | 经代表性客户零件验证，能够接入明确的目标 CAD 并按合同恢复 | M5 样本库/互操作与 M6 恢复演练报告 |
| 扩展领域资格 | 装配、PMI、图纸、复杂曲面等指定能力 | 各领域独立测试与适用范围声明 |

发布说明必须写出支持的操作、几何范围、内核版本和已知限制。不得用单个成功模型或长时间运行记录代替整个资格范围。

建议初始适用范围为一般机械零件，包围尺寸 1～1000 mm、最小设计特征 0.1 mm。这里是测试覆盖范围，**不是 OCCT 的数学能力边界**。超出范围返回 `OUTSIDE_QUALIFIED_ENVELOPE`，允许保留探索候选，受保护交付路径不得静默放行。

## 2. 固定基础与精度契约

### 2.1 内核与单位

- 权威几何：OCCT B-Rep；视口三角网格是派生表示，不能成为精密尺寸或 STEP 的来源。
- 规范单位：长度 mm、角度 rad、右手系、Z 向上；矩阵、向量乘法顺序、局部到世界转换由主协议固定。导入必须记录原单位和转换；不允许靠文件名或模型大小猜单位。
- Python 几何进程通过 OCP 直接访问经锁定的 OCCT API，返回操作历史与诊断。build123d 只可作为经过审查的构造辅助层，不得假定其封装自动保留所需拓扑历史。
- 内核、OCP、Python、适配器、操作契约、编译器、序列化器和容差配置固定版本；生产 Worker 使用固定镜像摘要。M0 检查实际加载版本，不能只读取依赖声明。
- 输入形状以不可变工件传递；并发任务使用隔离进程及私有形状实例。对支持该选项的布尔运算启用并验证非破坏模式；缓存中已发布输入的字节和语义身份不得被后续计算修改。

OCCT 布尔接口分别提供非破坏模式、模糊容差和错误报告等控制项，因此适配器必须显式选择参数并收集结果，不能将一个“布尔成功”布尔值当成完整契约。[OCCT Boolean API](https://occt3d.com/dev/doc/refman/html/class_b_rep_algo_a_p_i___boolean_operation.html)

### 2.2 精度配置分开定义

至少分开记录：建模工作容差、输出子形状最大容差、尺寸验收误差、测量算法误差、STEP 读写配置、派生网格弦差与角差。制造公差是设计要求，不能等同于这些数值误差。

每个测试夹具和工程使用具名 `precision_profile`，包含单位、版本、适用尺寸范围、全部阈值和测量方法。参数必须有限且合法；NaN、Infinity、负容差、非可逆空间转换等在进入内核前拒绝。

首个法兰夹具的建议配置如下；M1 达不到时必须报告并调整资格范围或实现，不能在后台调宽阈值。

| 配置项 | 草案目标 | 意义 |
| --- | --- | --- |
| `working_tolerance_mm` | 0.00001 mm | 经具体操作适配的数值策略，不是所有 OCCT 算法的统一开关 |
| `max_subshape_tolerance_mm` | 0.001 mm | 检查输出各顶点、边、面，超限拒绝 |
| `critical_dimension_error_mm` | ≤0.001 mm | 原生法兰关键解析尺寸的最大误差 |
| `step_roundtrip_dimension_error_mm` | ≤0.005 mm | 本资格配置中的 STEP 关键尺寸往返误差 |
| `volume_relative_error` | ≤0.000001 | 解析基准的相对体积误差；不能独立证明形状正确 |
| `measurement_error_budget_mm` | ≤0.0001 mm | 测量方法自身的误差预算；无法保证时返回 inconclusive |
| 视口弦差 | 单独配置 | 仅用于显示，不参与上述精密尺寸判断 |

不同零件可采用不同配置；不得把本表的某一数值作为整个软件的通用精度保证。输出报告同时保留所请求的阈值、实际设置、最大观测误差、测量算法及其版本。

接受条件为 `|测量误差| + 测量不确定性上界 <= 允许误差`；不能提供可信误差界时返回 inconclusive。STEP 的 0.005 mm profile 上限不能放宽 Goal 中更紧的硬尺寸要求：原生几何与重导入 STEP 都必须同时满足原 Goal 和该交换 profile，实际使用两者较严的阈值。

OCCT Shape Healing 能修正拓扑或几何，并可能调整容差。修复必须生成独立候选、差异和前后测量；即使设置了最大修复容差，仍检查最终子形状容差和所有硬尺寸要求。[OCCT Shape Healing](https://www.occt3d.com/dev/doc/overview/html/occt_user_guides__shape_healing.html)

## 3. 确定性验证与 Agent 权限

验证器使用受信任的 CAD 测量与检查代码。LLM 可以解释失败、建议修复、提出候选计划；不能自行写入“尺寸合格”证据、修改阈值或用视觉评分豁免硬约束。

按以下层次验证，每项均可返回 pass、fail、inconclusive。后两者均阻止正式交付。

1. **协议与参数**：类型、单位、作用域、有限数、参数范围、静态 DAG 无环、可用操作版本、输入工件完整性。
2. **内核结果**：API 完成状态、错误及警告策略、非空性、预期 Solid 数、闭合性和方向、B-Rep 有效性、子形状容差。合法空布尔结果必须与运算失败区分。
3. **设计尺寸**：从解析圆柱、平面、轴和受验证的测量方法检查孔径、孔距、厚度、半径、方向及位置关系，逐条对应 Goal 的硬条件。
4. **部件与集成**：指定接触关系、间隙、非预期干涉、部件数量及定位。单个零件有效不代表组合后的工程合格。
5. **编辑与交付**：重新加载原生工程后修改关键参数，重新计算、验证，再执行 STEP 导出及重新导入检查。

`BRepCheck_Analyzer` 提供 OCCT 的形状有效性检查及详细异常；其检查模式有具体范围，不能由 `IsValid()` 推导出设计尺寸或制造要求已经满足。报告记录 GeomControls、所用精确检查模式及不可执行的检查项。[OCCT BRepCheck_Analyzer](https://www.occt3d.com/dev/doc/refman/html/class_b_rep_check___analyzer.html)

禁止只用包围盒、体积或渲染相似度证明两个零件等价：同样包围盒和体积可以对应不同孔位或内部结构。对于非解析表面，表面距离检查必须说明覆盖域、精度界和未覆盖区域；只有采样结果时不得声称已经证明全局几何等价。

## 4. Feature、约束与拓扑引用

### 4.1 首批编译能力

初期采用静态 Feature DAG、显式参数和输入端口。先实现有固定原点与方向、可直接确定尺寸的 RectangleProfile / CircleProfile，再实现 Extrude、Revolve、Union、Subtract、刚体 Transform、参数更新、Tessellate 和几何检查。具体操作须通过 M0 后才能进入注册表的 `qualified` 集合。

Fillet 是 M4 的必测操作，在完成其成功及失败资格测试前不向工业交付开放。一般缩放、复杂放样、曲面修复、自动特征识别等不得仅因底层存在 API 就被标记为支持。

OCCT 几何运算不替代完整的交互式草图约束求解器。初期支持参数化锚定轮廓和有界表达式求值，明确没有通用欠约束草图求解能力。以后引入求解器时，另行固定许可证、DOF、冗余/矛盾分类、求解分支、数值收敛及解选择规则；失败不能伪装成“自动选择了合理位置”。

延期：运行时场景查询依赖、SwitchFeature、通用优化求解、逻辑图自动重写和 e-graph。先做反向依赖失效与内容寻址缓存；执行优化不得改变用户可见 Feature 身份、参数接口和编辑历史。增量求值必须与全量重算在同一资格配置下比较。

### 4.2 引用必须绑定真实几何

子形状引用至少包含 producer Feature、输出端口、绑定工件摘要、选择器、预期拓扑类型、候选数量约束和重绑定策略。禁止把 `Face_12` 或序列化遍历顺序视作跨重算稳定身份。

初期支持：显式基准、受资格测试的生成语义角色、绑定指定工件的局部子形状。每项操作声明历史追踪支持的实体种类、完整程度、缺失情况；能力不得压缩成一个容易误解的“支持拓扑历史”开关。

拓扑历史保存旧/新工件、操作身份、生成/修改/删除关系、split/merge 的多对多映射及来源证据。解析必须检查目标仍属于当前输出、实体类型、方向和 cardinality。零个候选返回 unresolved；要求 ExactlyOne 而出现多个候选返回 ambiguous；不能按排序或置信度默选。

恢复结果写入显式解析报告；无法证明兼容时阻止依赖 Feature 发布，保留已提交的最后一个有效版本。Agent 可以提出新的选择规则，但受相同验证约束。未资格化的引用重定位方法不进入自动交付路径。

OCCT OCAF 的命名机制依赖操作历史、历史加载和选择重求解三者一致。仅拿到 Generated/Modified 信息并不能自动得到完整的应用级稳定命名系统。应用 Feature DAG 与版本事务仍由项目协议拥有；若采用 TNaming，其文档及重放边界须另行资格验证。[OCCT OCAF](https://occt3d.com/dev/doc/overview/html/occt_user_guides__ocaf.html)

## 5. 原生可编辑工程与 STEP 是两种交付物

**原生工程包**至少包含场景/Feature 定义、参数与单位、稳定身份、依赖、绑定工件、几何 BREP、拓扑历史、操作及内核版本、精度配置、验收证据和校验清单。导入原生包后必须能够在固定兼容环境中修改参数、重算和再次导出；只有 BREP 或 STEP 文件不能作为“参数化历史可恢复”的证明。

**STEP 基线**先资格验证 AP214 的精确几何与明确声明的名称/结构子集。AP242、PMI、GD&T、材料、完整装配层次分别设置能力门禁；不能把“选用 AP242”解释为这些内容均能完整互换。实际协议、导出选项、单位、传递警告和目标软件版本写入报告。

OCCT 的基本 STEP 路径处理几何、拓扑及装配结构；名称、颜色、验证属性等附加信息通过 XDE/STEPCAF 路径提供，因此交付清单必须区分普通形状写出与所声明的 XDE 元数据能力。[OCCT STEP Translator](https://www.occt3d.com/dev/doc/overview/html/occt_user_guides__step.html)

每次资格测试保存：原生输入、导出文件、重新导入工件、读写状态、实体/部件数量、单位、关键尺寸、曲面类型、体积/面积/质心和几何检查差异。允许导入后局部编号发生变化，不得依赖原生 Subshape ID 在 STEP 中保持不变。

同一个 OCCT 版本写出再读回只证明该路径的往返行为。M5 必须增加至少一种目标客户 CAD 的独立接收测试，记录产品和版本；其他 CAD 不因此自动获得互操作资格。无法取得目标软件时，该门禁保持未通过。

## 6. 首个确定性夹具：带孔安装法兰

M1 基准不含圆角，采用 Z 轴向上的单实体法兰：

| 项目 | 定义 |
| --- | --- |
| 外径 | 100 mm，轴线为世界 Z 轴 |
| 厚度 | 12 mm，下表面 z=0，上表面 z=12 |
| 中心通孔 | 直径 30 mm，与外圆同轴 |
| 安装孔 | 4 个直径 8 mm 的贯穿孔 |
| 孔中心 | (35,0)、(0,35)、(-35,0)、(0,-35) mm |
| 实体 | 1 个闭合、方向正确的 Solid |
| 解析体积 | π × (50²−15²−4×4²) × 12 = 26532π mm³ |
| 编辑参数 | 外径、厚度、中心孔径、安装孔径、孔分布圆直径 |

体积和包围盒作为交叉检查；正式验收逐项检查外圆柱/内圆柱的半径、轴线、孔中心和贯穿关系。枚举误删一个孔、孔位偏移、误用半径/直径、mm/m 混淆、负向厚度和多余实体等反例，验证检查器确实会拒绝。

M4 增加外圆上缘 1.5 mm 圆角；此时不得继续沿用未倒圆角的解析体积公式。通过对应半径/曲面与相邻关系检查、整体 B-Rep 检查和增量/全量比较验证。超大圆角半径、选错边、所选边被删除或分裂必须产生可定位失败，不能接受未倒圆角的原形作为成功输出。

## 7. 开发门禁

| 门禁 | 要完成的工作 | 通过要求 |
| --- | --- | --- |
| M0：内核/构建资格 | 锁定 OCP/OCCT 与构建环境，验证单位、序列化、进程隔离、操作诊断、历史输出及 STEP 路径 | 干净环境重建；版本实际匹配；支持矩阵中的每项附成功/拒绝测试；异常进程不污染输入 |
| M1：确定性 CAD 闭环 | 固定 IR、静态 DAG、法兰夹具、工件和原生包、基础 STEP 往返 | 不依赖 LLM 可重复完成夹具；解析尺寸与反例全部通过；原生重载后编辑与重算通过 |
| M2：持久化与原子发布 | 任务/租约/栅栏、候选、绑定证据、分支 CAS、事务发布与恢复 | 重复提交只产生一次正式效果；租约/目标过期拒绝；故障前后工程、Evidence 与 Task 状态一致 |
| M3：Agent 编辑与失败修复 | 自然语言到受检 IR，关键尺寸变更、失败诊断、有界修复、审批与重规划 | 运行中改目标和崩溃恢复均遵守权限；Agent 不得放宽精度或篡改合格事实 |
| M4：工程功能 | 圆角、有限草图约束、语义孔/阵列、刚性装配/BOM、迁移 | 引用歧义失败可定位；受支持编辑及集成条件均可验证 |
| M5：工业几何与交换资格 | 扩大工业样本库、独立目标 CAD 互操作 | 对冻结集合提交可复查报告；缺失能力明确列出 |
| M6：限定范围工业试用 | 安装升级、连续运行、故障恢复与耐久性演练 | M5 与具名部署恢复指标均通过，提交工业试用范围声明 |

每个门禁完成后才能扩大承诺范围。M1 通过可称确定性原型；M2 通过可称可靠运行时基础；未经 M5～M6 不能仅凭两者宣称工业试用资格。

M5 建议先建立至少 30 个冻结夹具，覆盖棱柱零件、回转零件、薄壁/近相切/共面边界、圆角极限、导入 STEP 和历史引用变更；每类包含预期成功及预期拒绝。数量是最初建设目标，覆盖矩阵比总数更重要。每次发布保存分母、通过数、失败数、拒绝符合率与新增回归；不得通过删除失败样本提高成功率。

另设至少 500 组有界、固定种子的参数组合测试作为建议起点。性质测试包括：单位等价、刚体变换前后体积保持、厚度改变后的解析体积关系、无关参数修改不影响输出、增量/全量一致、序列化重载保持语义。随机数据须符合声明域；不合法数据测试预期拒绝，不能混入成功率分母。

72 小时故障浸泡在 M6 执行，记录实际工作量、空闲时间、故障种子、恢复和有效进展。它检查持久化与恢复能力，不证明数值精度、设计质量或整个工业资格范围。

## 8. 可恢复性及发布证据

以下为建议 SLO，需在具名部署环境中测量后才能对外承诺：

| 故障域 | 建议目标 | 门禁方法 |
| --- | --- | --- |
| Worker/API 单进程崩溃 | 对已确认发布 RPO=0；依赖健康后 5 分钟内恢复可调度 | 强制终止进程，核对提交、证据、预算与租约；恢复从已持久化 Feature 边界继续 |
| DB 主实例故障 | 由同步持久化/复制拓扑决定；目标为已确认事务不丢失 | 故障切换演练验证 WAL、对象工件和分支引用；不能由单机事务推导跨站 RPO=0 |
| 备份级灾难恢复 | 初始建议 RPO≤15 分钟、RTO≤4 小时 | 从独立备份恢复并核对版本、工件、审计和访问权限；目标取决于实测数据规模 |

Geometry Worker 进程内存不是恢复点。丢失未物化的操作允许重算；已确认提交必须引用已持久化、可校验的工件。数据库与对象存储的备份/保留策略必须能恢复同一个引用闭包；“数据库恢复成功但几何缺失”不算恢复通过。

每次发布报告至少包括：Git 提交、构建镜像及依赖摘要、资格配置、完整输入与种子、验证器版本、成功/失败/不确定数量、关键尺寸最大偏差、子形状最大容差、STEP 目标 CAD 与版本、故障恢复测量、已知问题及范围变化。门禁失败保留报告和候选，不更新资格声明。

## 9. 扩展路线的独立资格项

| 后续能力 | 需要补齐的实质工作 |
| --- | --- |
| 草图约束 | 求解器集成与许可，DOF/冗余/矛盾诊断、稳定解与编辑行为 |
| 装配与 BOM | 零件/实例区分、装配约束、干涉/间隙、层级/数量/版本及 STEP 接收检查 |
| PMI / GD&T | 设计语义、基准与几何关联、AP242 可用子集、目标 CAD 读写及断链检查 |
| 工程图 | 视图、剖视、隐藏线、尺寸与模型关联、更新与导出验收 |
| 复杂曲面 | 曲面质量、连续性、容差增长、修复损失与特定工业数据集 |
| 自动图优化 | 先定义可观察行为和身份保留，再做等价证据、编辑回归与性能比较 |
| 跨内核/跨版本迁移 | 保留原始工件；影子重算、几何与引用比较，通过后产生新版本 |

工业资格是对受测版本和适用范围的承诺。每增加一种操作、放宽一个几何边界或升级一次内核，都需要对应的资格证据；已有工件与历史版本继续可读，不能被后台升级静默改写。
