# 产品原则：持续受托的工程 Agent

依据：用户在本次会话补充的产品视角。状态：产品方向基线，具体渠道与商业模式尚未实施。

## 产品的主要工作对象

用户委托一个具有目标、约束、预算和验收条件的工程任务。任务持续存在于云端，独立于编辑器、设备、对话和模型调用；Agent 在授权范围内安排并发工作、等待外部结果、验证、修复和交付。关闭界面不终止任务。

极简入口用于表达意图、查看结果和处理关键决定。未来可增加语音或消息渠道，但工程数据和控制权限均属于同一 Project/Run，不能为各渠道建立互不一致的任务状态。目前不选择、接入或发送任何即时消息/电话服务。

## 渐进展开的交互

默认交互只呈现目标、当前结果、阻塞原因和所需决定。专业工作台按需展开，用于尺寸、公差、子拓扑和装配关系的检查与接管；工程师仍可直接修改参数和特征。对复杂几何的视觉/精确验证与简洁入口共同构成体验。

通知只有三类：有价值的交付、需要用户决定、明确阻塞或失败。普通执行、重试、等待和无变化状态在后台记录，不默认反复通知。长任务应显示可查询的状态和预期下一步，而不要求用户持续阅读聊天记录。

每条消息先呈现结果及需要的动作，关键信息位于开头约 30%：

> 盖板已完成。孔距与法兰不匹配，需要你选择沿用原孔距或调整盖板。尺寸差异和候选模型可展开查看。

展开层包含受影响参数、修改前后几何、尺寸证据、成本及版本。用户审批绑定具体候选；语音或消息确认也必须对应清楚的候选内容、动作和范围，含糊回复不能被当作无限授权。

## 后台自主与用户利益

24 小时可推进意味着持久任务、可靠唤醒和故障恢复；等待时可以释放计算资源。有效进展按设计条件和真实交付证据衡量，不能以在线时长、对话长度或通知频率充当成绩。

用户长期记忆按来源、版本、工程权限与有效期管理。设计偏好帮助执行，不覆盖当前尺寸要求；Agent 不得借助长期记忆扩大权限、放宽公差或更改预算。

用户表达了长期免费、避免广告干预和探索交易佣金的愿望。当前工业 CAD 开发不依赖该商业模式成立。未来若引入采购/加工服务，用户的技术条件、价格与利益应优先于佣金；商业关系要清楚标注，不能暗中改变工程验收或引导额外购买。交易授权与建模授权分别处理。

## 对当前研发的约束

- 先证明不依赖聊天会话的确定性 CAD 能力，再接入持续委托与长程 Agent。
- Project、Run、Goal、候选、证据、审批与交付均可由不同入口查询，所有控制经过同一受信任服务。
- 最小工作台围绕结果检查和工程接管建设；消息入口围绕意图和决策建设。
- 测量交付成功率、有效自主工作跨度、必要人工决策次数与质量、恢复可靠性及总成本。
- 工业精度、可编辑性和可恢复性持续作为底线；入口简洁不削弱工程证据。
