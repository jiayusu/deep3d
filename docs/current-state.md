对照基准：[目标状态契约 v1.0](target-contract-v1.md)。设计方案：[系统设计 v1.0](system-design-v1.md)。本文件是实现范围盘点，不是正式冻结验收的一次观测记录。

## 已有的可运行基础

- Rust 保存类型化参数、Scene、Feature DAG、命令和不可变版本，原生工程可以重开编辑。
- 已接入 [0.3.0 机械操作集](cad-capabilities.md)：约束草图、实体操作、修饰、孔/阵列和刚性多组件结构。
- 原生/STEP 独立进程检查，命名装配与 BOM，失败结果不登记为成功物化。
- PostgreSQL 固定任务图、多个 Worker、租约、控制撤权、恢复和结果下载。
- GoalRevision / PlanRevision / VerifiedCommit / PublicHead 已进入 PostgreSQL：只有绑定当前目标、经协调服务新鲜独立验证的最终任务才推进公开版本；私有前置任务、过期或失权回写、缺证据的候选都不会公开。
- C01～C10 的可编辑原生种子已建立；变化按定义、草图求解、几何、放置、交付、证据分类，改名只影响交付，移动实例不重算共享零件。
- Feature 级失效计划带原因边（`deep3d explain` 可查询哪些 Feature 失效、为什么、哪些复用）；ActionCache 按内容寻址复用未失效 Feature 的原 BREP 字节，开发样例上实际执行集合等于解释的失效集合，并与禁用缓存的全量重建逐项几何等价。

已有的工程回归与三个机械源样例不冒充 10 个预注册自然语言任务或 V0.1 整体成绩。公开仓库、文档存在也不代表许可证与独立复现要求已经满足。

本轮实际检查范围与复查命令见 [机械 CAD 工程回归](../qualification/mechanical/README.md)。2026-10-28 在 Linux 云容器（PostgreSQL 16）复查：Rust 工作区 70 项、Python/OCCT 374 项通过（含 G5 真实进程回归 2 项）；此前 Linux 上虚拟环境解释器被解析为系统 Python 导致原生求值失败，已修复。

本环境没有可用的模型服务凭据；G1、G6 与 R05 需要真实模型执行，不能用脚本化规划替代。

## 接下来按用户结果推进

1. 由独立审阅者复核 C01～C10 种子、角色绑定、oracle 与恢复场景驱动，冻结注册表和清单。
2. 接入可用的模型服务，把自然语言入口接到 GoalRevision，补 G1、G6 与 R05 的模型切换。
3. 自然语言入口通过可替换规划者提交稳定 IR；补模型查看、差异、接管和证据入口。
4. 完成独立验收资产、种子图和运行器后冻结注册表，运行 G1～G7；在具备持续接受/恢复能力后实际启动 G6。
5. LH-001 使用同一系统另行执行，保存真实跨度、要求变更、中断恢复和成果证据。
